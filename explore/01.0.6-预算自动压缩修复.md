# 01.0.6 预算自动压缩修复（compactNow → compactIfNeeded）

> 2026-11-18 ｜ 依据：诊断日志 + compaction-basic 源码核对 + 子 agent 全链路实测 ｜ 提交 `f275dcd`

## 1. 背景：一个隐藏已久的老 bug

dsh-dashboard 的「token 预算」功能设计为：`agent/pre-step` 阶段测量会话 token，超预算自动压缩。
此前功能清单里一直标 ✅，但**压缩从未真正发生过**——对顶层会话和子 agent 都一样，只是错误被 `catch {}` 静默吞掉了。

首次实锤来自「限制子 agent 上下文」探索：给 qwen 子 agent 会话设 budget=2048，子 agent 实际用到 1 万+ token，会话日志里却零个 `compaction/*` 事件。

## 2. 根因（诊断日志给出决定性证据）

给 budget 检查加了 `~/.dsh/dsh-dashboard/budget-debug.log` 文件日志（`ctx.logger` 输出位置不稳定，文件日志保证可读），复现后：

```
pre-step sid=1f2222c0... totalTokens=10875 budget=2048 → 触发压缩
pre-step sid=1f2222c0... compactNow 抛错: ManualCompactionError:
  manual compaction requires an idle agent with no waking queued work
```

结论：**`measure` 完全正常，是 `compactNow` 用错了接口。**

`compaction.compactNow(agent)` 内部走 `agent.runMaintenance()`，**要求 agent 处于 idle**；而预算检查挂在 `agent/pre-step` 阶段，此时 agent 正在运行 → 必然抛 `ManualCompactionError("busy")`，被原 `catch {}` 静默吞掉。

## 3. 修复

触发压缩的调用从 `compactNow` 改为 `compactIfNeeded(agent, 'context-overflow', signal)`：

- `compactIfNeeded` 只要求 `CompactionAgentContext`（session + options），**不要求 idle**；
- 它内部就是 `selectCompactableRange(..., 0) + compactRegion`，压缩策略与 `compactNow` 一致；
- `context-overflow` 触发器是官方「非 idle 阶段强制压缩」路径（`pressure` 触发器会按 0.8×contextWindow 阈值返回 null 不压缩，故不可用）。

同时去掉静默 catch：budget 检查四个环节（取 sid / 取 compaction / measure / 触发压缩）分别 try/catch 记录到 budget-debug.log，错误不再吞掉。

## 4. 验证（全链路实证）

修复后重载插件，子 agent 会话设 budget=2048 并唤醒工作：

1. 诊断日志：`totalTokens=11338 → 触发压缩`，`compactIfNeeded 返回 {shadowed:9, tokens:1546}` ✅
2. 子 agent 会话持久化日志出现完整 **`compaction/start` → `compaction/summary` → `compaction/end`** 三件套 ✅

预算现在真正覆盖子 agent 与顶层会话。

## 5. 附带的机制事实（供后续参考）

- `ctx.compaction` 抽象三接口，选型要点：
  - `compactNow(agent)`：要求 idle（`runMaintenance`）——**只能用于手动清空/命令，不能用于 pre-step**；
  - `compactIfNeeded(agent, trigger)`：`pressure` 按模型阈值、`context-overflow` 强制压缩——**pre-step 自动压缩用 `context-overflow`**；
  - `compactRegion(start, end, agent)`：直接压缩指定 span，需自行保证边界 balanced。
- `budget-debug.log` 仅对「设置了预算」的会话记录（无预算直接放行，避免每会话每步写日志）。
- 此 bug 不涉及子 agent 事件作用域问题——子 agent 的 `agent/pre-step` 一直能到达插件监听器（与官方 compaction-basic 同挂载方式），问题只在 compactNow 的 idle 约束。
