# 01.0.7 Qwen 32K 自动压缩失效（headroom 把压力预算算成负数）

> 2026-11-18 ｜ 依据：compaction-basic 源码核对 + 会话日志实证 + 数值复算 ｜ 修复于 profile patch

## 1. 现象

「复杂任务问答记录」会话（`session-b1abddca…`，模型 local-qwen Qwen3-14B，contextWindow=32768）上下文被 `find` 输出撑爆后**没有自动压缩续跑**，直接「输出 token 上限截断」。整个会话持久化日志里**零个 `compaction/*` 事件**。

用户观察：DeepSeek 1M 用完会压缩然后开新一轮，Qwen 32K 却直接卡死。

## 2. 根因（源码级）

compaction-basic 的 `resolveCompactSpec`（config.ts）计算压力预算：

```
messageBudgetTokens   = contextWindow − reservedCompletionTokens
pressureBudgetTokens = messageBudgetTokens − headroomTokens
```

默认 `headroomTokens = 65536`（config.ts 第 63 行 `?? 65_536`），而 Qwen 窗口只有 32768：

```
pressureBudgetTokens = 32768 − 0 − 65536 = −32768 ≤ 0
```

`pressureBudgetTokens <= 0` → 抛 `TargetPressureConfigError`。

而 pre-step 监听器捕获该错误后：

```js
catch (error) {
  if (error instanceof TargetPressureConfigError) {
    if (this.warnedPressureConfigTargets.has(error.targetKey)) return next()  // 之后永久跳过
    this.warnedPressureConfigTargets.add(error.targetKey)                     // 只 warn 一次
  }
  ctx.logger.warn(`step compaction failed: ${message}; continuing the turn`)
}
```

**第一次 warn 后加入黑名单，此后每次 pre-step 直接 `return next()`，压力自动压缩对 Qwen 永久失效。**

## 3. 为什么 DeepSeek 1M 正常

| | DeepSeek 1M | Qwen 32K（修复前） |
|---|---|---|
| contextWindow | 1048576 | 32768 |
| headroomTokens（默认） | 65536 | 65536 |
| pressureBudget | 983040 > 0 ✅ | −32768 ≤ 0 ❌ |
| 触发压缩 | ~838860（0.8×1M） | 永不 |

不是「Qwen 没有压缩能力」，而是**默认余量 65536 比整个 32K 窗口还大，把压力预算算成了负数**。

## 4. 修复

profile patch（`~/.dsh/profiles/desktop/cordis.patch.yml`）给 compaction-basic 配 modelPolicies：

```yaml
- id: compaction-basic
  name: "@deepseek-ai/dsh-compaction-basic"
  config:
    modelPolicies:
      - provider: local-qwen
        model: Qwen3-14B-Q4_K_M.gguf
        headroomTokens: 8192
        thresholdRatio: 0.7
```

复算（reservedCompletionTokens=0，retainRatio 默认 0.16）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| messageBudget | 32768 | 32768 |
| pressureBudget | −32768 ❌ | 24576 ✅ |
| thresholdTokens（触发压缩） | — | 22937（~0.7×32K） |
| retainTokens（保留近期） | — | 5242 |

## 5. 生效方式

profile patch 层需**重启 DSH** 才装载（`.volatile()` 字段才热更新）。影响所有用 local-qwen 的会话（父 + 子 agent）。

## 6. 附带的机制事实

- `compactIfNeeded('pressure')` 走 `resolveCompactSpec` 阈值判定，配置错误会静默降级（warn 一次后永久跳过）——**这是静默失败，不是显式报错**，排查要靠会话日志无 compaction 事件 + 复算预算反推。
- `compactIfNeeded('context-overflow')` 是 provider 确认溢出后的恢复路径，与 pressure 独立；本次会话失败是「输出 token 上限截断」而非 provider overflow，两条路径都没触发。
- 与 01.0.6 的区别：01.0.6 修的是「预算触发压缩用错接口（compactNow 要 idle）」，01.0.7 修的是「compaction-basic 自身的压力压缩对 32K 窗口被 headroom 默认值废掉」——两处独立，都影响自动压缩兜底。
