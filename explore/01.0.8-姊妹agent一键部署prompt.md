# 01.0.8 姊妹 agent prompt · 一键部署 cloud-token-pool + dsh-dashboard

> 交付对象：cloud-token-pool 维护 agent（对方域）。本文件是可直接粘贴的开工 prompt。
> 你（dsh-dashboard 维护者）只提供本 prompt；一键安装脚本的实现与落地由对方执行并回验。

---

你是 cloud-token-pool 的维护 agent。现在把 **cloud-token-pool（号池网关）** 与 **dsh-dashboard（DSH 会话控制台插件）** 做成**一条命令的一键部署**：`git clone 后 ./install.sh` 一次装完两样，DSH 重启后同时得到「号池模型 provider + 控制台插件（含号池用量按钮）」。

## 一、你已有的（cloud-token-pool 侧，照旧）

- `install.py`：搜 cordis.patch.yml（--profile > DSH_PROFILE_DIR > Mac ~/.dsh/profiles > Win 兜底）→ 幂等注入 provider + 切默认模型（`=== pool-gateway ===` 标记 + `.pre-pool.bak` 备份）→ 设环境变量 → 启网关；
- 网关 `http://127.0.0.1:7862`：`/v1/chat/completions`、`/v1/messages`、`GET /balance?json=1`（字段：`at`、`accounts[].name/live/available/disabled{reason}/month_in_tokens/month_out_tokens/month_credits_est/cache_at`）。

## 二、dsh-dashboard 插件侧（对方域事实，按此实现，勿改其仓库）

**仓库**：`git@github.com:longjincf/dsh-dashboard.git`（main）。零 npm 依赖；helper 运行时用 Electron 44.7.0（首次开外窗自动从 npmmirror 下载到 `~/.dsh/dsh-dashboard/electron/`，需 SHA256 校验的下载逻辑已在插件内）。

**安装三件事（全部幂等、带标记、可回滚）**：

1. **链接进 profile**：
   - `mkdir -p <profileDir>/node_modules`
   - `ln -sfn <dsh-dashboard目录> <profileDir>/node_modules/dsh-dashboard`
   - 在 `<profileDir>/package.json` 的 `dsh.profile.bundles` 数组追加 `"dsh-dashboard"`（已存在则跳过；无该文件则按现有结构创建最小 package.json）。

2. **注入 patch 行**（追加到 cordis.patch.yml，标记 `# === dsh-dashboard ===`，注入前自动备份）：
   ```yaml
   - insert:
       - id: dsh-dashboard
         name: 'dsh-dashboard'
         config:
           enabled: true
           poolUrl: 'http://127.0.0.1:7862'
   - id: compaction-basic
     name: '@deepseek-ai/dsh-compaction-basic'
     disabled: false
     config: {}
   ```
   （第二行是控制台「清空上下文」的依赖，web 组合默认禁用，需插件层启用。）

3. **重启 DSH** 生效（patch 层必须重组才装载，无热更新）。

**验证清单**（安装完成后逐条回验）：

| 项 | 期望 |
|---|---|
| DSH 设置 | 出现「控制台设置」节（插件行 `include:dsh-dashboard` active） |
| 齿轮 | 右下角 ⚙ 出现（总开关默认 off，设置里开启） |
| 外窗 | 「打开外窗」后透明置顶窗出现（首次会下载 Electron ~124MB） |
| 号池用量 | 外窗顶栏「池」按钮 → 区块显示三号余额（走 helper→**宿主**→7862；**helper 进程受 DSH 沙箱限制不能直连 7862，必须经宿主反代**，插件已实现，poolUrl 可配） |
| 模型 | 会话模型选择器出现 `pool-qwen`/`pool-glm`（你方 install.py 的职责，两套 patch 共存于同一文件，各自标记互不干扰） |

## 三、必须遵守的边界与坑

1. **双方 patch 共存**：你的 `=== pool-gateway ===` 段与插件的 `=== dsh-dashboard ===` 段在同一 cordis.patch.yml，都用标记+备份+幂等；回滚互不影响；
2. **行 id 不冲突**：dsh-dashboard / compaction-basic 已被插件占用，你方不要再用这两个 id；
3. **数据契约**：`/balance?json=1` 字段如变更，同步更新 dsh-dashboard 的 `runtime/helper/standalone.html` 渲染逻辑并在 README 注明（对方域会跟进）；
4. **安全**：7862/8792 都只绑 127.0.0.1；`/balance` 不返回任何 key；插件侧 pool 路由带随机 token；
5. **平台**：dsh-dashboard 外窗目前 **macOS 优先**（Electron.app 路径假设）；Win11 上齿轮/设置页可用但外窗不可用——安装脚本在 Windows 上跳过步骤 1 的 node_modules 链接外的外窗依赖即可，文档注明；
6. **顺序**：先注入 provider（你方）后注入插件（我方）或反之均可，最终都需**一次 DSH 重启**；
7. **回滚**：删标记段 + 删 bundles 里的 dsh-dashboard + 删链接，重启 DSH 即还原。

2. 真机跑一遍全链路（Mac），把验证清单结果填好回执；
3. 若遇插件侧问题（不是脚本 bug），不要改 dsh-dashboard 仓库——把现象报回来，由对方域处理。
